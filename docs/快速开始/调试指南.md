# 调试指南

> 本文档记录 STM32F407 项目的调试方法、常见问题排查和实用技巧。

---

## 调试环境配置

### 工具链

| 工具 | 版本建议 | 用途 |
|------|----------|------|
| OpenOCD | 0.12+ | 调试服务器 |
| arm-none-eabi-gdb | 12.x+ | GDB 调试器 |
| Cortex-Debug | 最新 | VS Code 调试插件 |
| CMSIS-DAP | - | 调试器硬件 |

### VS Code 调试配置

调试配置位于 `.vscode/launch.json`：

```json
{
    "name": "Cortex Debug",
    "type": "cortex-debug",
    "request": "launch",
    "servertype": "openocd",
    "cwd": "${workspaceFolder}",
    "executable": "${workspaceFolder}/build/firmware-gcc/app.elf",
    "configFiles": [
        "interface/cmsis-dap.cfg",
        "target/stm32f4x.cfg"
    ],
    "svdFile": "${workspaceFolder}/.vscode/STM32F407.svd"
}
```

## 常见问题排查

### 1. 无法连接调试器

**现象**：OpenOCD 报错 `Error: unable to find a matching CMSIS-DAP device`

**排查步骤**：
1. 检查 USB 连接和驱动
2. 确认调试器模式（SWD/JTAG）
3. 降低适配器速度：
   ```bash
   openocd -f interface/cmsis-dap.cfg -c "adapter speed 500" -f target/stm32f4x.cfg
   ```
4. 检查 NRST 引脚是否连接

**常用速度设置**：
- 稳定连接：500 kHz
- 正常调试：1000 kHz
- 高速下载：4000 kHz

### 2. 程序无法运行/卡死

**排查清单**：

| 检查项 | 方法 |
|--------|------|
| 时钟配置 | 检查 HSE 是否起振，PLL 配置是否正确 |
| 向量表 | 确认 SCB->VTOR 指向正确地址 |
| 堆栈溢出 | 检查 _estack 设置，使用 MSP 监控 |
| HardFault | 查看 CFSR/HFSR 寄存器 |

### 3. HardFault 调试

当程序进入 HardFault_Handler 时，按以下步骤排查：

**步骤 1：读取故障寄存器**

在调试器中查看以下寄存器：
- `SCB->CFSR` (0xE000ED28) - 可配置故障状态
- `SCB->HFSR` (0xE000ED2C) - 硬故障状态
- `SCB->MMFAR` (0xE000ED34) - 内存管理故障地址
- `SCB->BFAR` (0xE000ED38) - 总线故障地址

**步骤 2：解析 CFSR**

```
CFSR 各位含义：
[31:16] UFSR - 用法故障
  [25] DIVBYZERO - 除零错误
  [24] UNALIGNED - 非对齐访问
  [19] NOCP - 无协处理器
  [18] INVPC - 无效 PC
  [17] INVSTATE - 无效状态
  [16] UNDEFINSTR - 未定义指令

[15:8] BFSR - 总线故障
  [15] BFARVALID - BFAR 有效
  [12] STKERR - 入栈错误
  [11] UNSTKERR - 出栈错误
  [10] IMPRECISERR - 不精确错误
  [9] PRECISERR - 精确错误
  [8] IBUSERR - 指令总线错误

[7:0] MMFSR - 内存管理故障
  [7] MMARVALID - MMFAR 有效
  [4] MSTKERR - 入栈错误
  [3] MUNSTKERR - 出栈错误
  [1] DACCVIOL - 数据访问违规
  [0] IACCVIOL - 指令访问违规
```

**步骤 3：定位故障代码**

```c
// 在 HardFault_Handler 中添加调试代码
void HardFault_Handler(void) {
    __asm volatile (
        "tst lr, #4          \n"
        "ite eq              \n"
        "mrseq r0, msp       \n"
        "mrsne r0, psp       \n"
        "b hard_fault_handler_c \n"
    );
}

void hard_fault_handler_c(uint32_t *hardfault_args) {
    volatile uint32_t stacked_r0 = hardfault_args[0];
    volatile uint32_t stacked_r1 = hardfault_args[1];
    volatile uint32_t stacked_r2 = hardfault_args[2];
    volatile uint32_t stacked_r3 = hardfault_args[3];
    volatile uint32_t stacked_r12 = hardfault_args[4];
    volatile uint32_t stacked_lr = hardfault_args[5];   // 返回地址
    volatile uint32_t stacked_pc = hardfault_args[6];   // 故障指令地址
    volatile uint32_t stacked_psr = hardfault_args[7];

    volatile uint32_t cfsr = SCB->CFSR;
    volatile uint32_t hfsr = SCB->HFSR;
    volatile uint32_t mmfar = SCB->MMFAR;
    volatile uint32_t bfar = SCB->BFAR;

    // 在此处设置断点，查看上述变量
    __BKPT(0);
    while(1);
}
```

### 4. LED 不闪烁

**排查清单**：

1. **GPIO 时钟未使能**
   ```c
   __HAL_RCC_GPIOF_CLK_ENABLE();  // 必须先使能
   ```

2. **引脚配置错误**
   - 确认 LED 引脚（PF9/PF10）
   - 确认有效电平（低电平点亮）

3. **HAL_Delay 不工作**
   - 检查 SysTick_Handler 是否调用 HAL_IncTick()
   - 确认 uwTick 在递增

4. **时钟配置失败**
   - HSE 未起振 → 检查晶振焊接
   - PLL 配置错误 → 检查倍频系数

### 5. 串口无输出

**排查清单**：

| 检查项 | 说明 |
|--------|------|
| 引脚配置 | PA9(TX), PA10(RX) 是否正确配置为复用功能 |
| 波特率 | 确认与串口助手设置一致（115200） |
| 时钟 | USART1 时钟是否使能 |
| 连接 | TX-RX 交叉连接，共地 |
| printf 重定向 | 检查 _write() 或 fputc() 实现 |

## 调试技巧

### 1. 使用 ITM 打印（SWO）

比 UART printf 更快，不占用 USART 资源：

```c
// 启用 ITM
CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
ITM->LAR = 0xC5ACCE55;
ITM->TER = 0x1;

// ITM 打印函数
int _write(int file, char *ptr, int len) {
    for (int i = 0; i < len; i++) {
        ITM_SendChar(*ptr++);
    }
    return len;
}
```

### 2. 断点条件

在 VS Code 中设置条件断点：
- 右键断点 → Edit Breakpoint
- 输入条件：`i == 100` 或 `buffer[0] == 0xFF`

### 3. 内存监视

在调试控制台查看内存：
```
-exec x/16xw 0x20000000    # 查看 RAM 前 16 个字
-exec x/s 0x08001000       # 查看字符串
```

### 4. 寄存器监视

使用 SVD 文件在 Cortex-Debug 中直接查看外设寄存器：
- 打开 CORTEX PERIPHERALS 面板
- 展开 GPIOF、USART1 等外设查看状态

## OpenOCD 常用命令

```bash
# 基本连接
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg

# 烧录固件
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg \
  -c "program build/firmware-gcc/app.elf verify reset exit"

# 擦除芯片
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg \
  -c "init; reset halt; stm32f4x mass_erase 0; exit"

# 解锁芯片（读保护）
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg \
  -c "init; reset halt; stm32f4x unlock 0; exit"
```
