# 串口重定向（printf/stdio -> USART1）

本文说明本项目如何把 `printf/puts/fprintf(stdout/stderr, ...)` 重定向到 **USART1**（阻塞式发送），适用于 `arm-none-eabi-gcc` + `newlib-nano` 的工程结构。



## 快速上手（3 步）

1. 初始化串口：`MX_USART1_UART_Init()`（本项目：115200, 8N1）
2. 关闭缓冲：`retarget_stdio_init()`（让 `printf` 不等换行也立即输出）
3. 直接用：`printf("hello\\n");`

硬件连接与串口参数见“验证与排查”章节。

## 背景：newlib 的 `_write()` 钩子

本项目使用 `arm-none-eabi-gcc` + `newlib-nano`（链接参数含 `-specs=nano.specs`）作为 C 标准库实现；同时链接参数含 `-specs=nosys.specs`，用于提供一组默认系统调用桩函数。只要工程里实现了 `_write()` 且最终链接进 ELF，并且符号优先于 `nosys` 的默认桩实现，`printf()` 就自然“有地方输出”。

在 newlib 中，`printf/puts` 等最终会通过底层系统调用接口把数据写到“文件描述符”，典型就是：
- `STDOUT_FILENO`（1）
- `STDERR_FILENO`（2）

裸机工程没有操作系统的文件系统与终端设备，因此需要由工程提供 `_write()` 的实现，把“写 stdout/stderr”映射到某个物理输出通道（本项目选择 USART1）。

## 1. 总体调用链

在本项目中，典型输出路径如下：

```
printf("...")
  -> newlib: vfprintf(...) / _vfprintf_r(...)
    -> newlib: write(...) / _write_r(...)
      -> 工程提供: _write(file, ptr, len)
        -> uart_write(data, len)
          -> HAL_UART_Transmit(&huart1, ...)
            -> USART1 TX
```

关键点：只要链接时把工程里的 `_write()` 链接进最终 ELF（并且符号优先于 `nosys` 的默认桩实现），`printf()` 就自然“有地方输出”。

## 2. 相关文件与关键符号

- `firmware/CMakeLists.txt`
  - `target_sources(... retarget.c ...)`：把重定向实现编进 `app.elf`
  - `target_link_options(... -specs=nosys.specs -specs=nano.specs ...)`：启用 newlib-nano 与默认系统调用桩
- `firmware/app/src/retarget.c`
  - `void retarget_stdio_init(void)`：关闭 stdout/stderr 缓冲
  - `int _write(int file, char *ptr, int len)`：把 stdout/stderr 输出写到 UART
- `firmware/app/inc/retarget.h`
  - `retarget_stdio_init()` 声明
- `firmware/drivers/uart/uart.c`
  - `UART_HandleTypeDef huart1`：USART1 句柄
  - `void MX_USART1_UART_Init(void)`：初始化 USART1
  - `int uart_write(const uint8_t *data, size_t len)`：阻塞式发送封装
- `firmware/app/src/stm32f4xx_hal_msp.c`
  - `HAL_UART_MspInit()`：USART1 GPIO 复用配置（本项目使用 `PA9`/`PA10`，AF7）
- `firmware/app/src/main.c`
  - 在 `MX_USART1_UART_Init()` 之后调用 `retarget_stdio_init()`

## 3. 初始化流程（main 中的顺序）

本项目当前在 `main()` 里按如下顺序初始化：

1. `HAL_Init()`
2. `SystemClock_Config()`
3. `MX_GPIO_Init()`
4. `MX_USART1_UART_Init()`（准备好串口外设与 `huart1`）
5. `retarget_stdio_init()`（关闭缓冲，保证 `printf` 立即输出）
6. `printf("UART retarget ok ...")`

要求：必须先完成 `MX_USART1_UART_Init()`，否则 `_write()` 里调用 `uart_write()` 会使用尚未初始化的 `huart1`。

## 4. `retarget_stdio_init()`：关闭缓冲的意义

实现要点：

- 对 `stdout/stderr` 调用 `setvbuf(..., _IONBF, ...)` 关闭缓冲。

这样做的目的：
- 在裸机调试阶段，希望日志“立刻”从串口出去；否则可能因为缓冲策略（例如行缓冲/全缓冲）导致你不换行、不缓冲满就看不到输出。

注意：关闭缓冲会增加 UART 发送调用次数（更频繁），但换来更可预期的实时性，适合 bring-up 阶段。

## 5. `_write()`：如何把 stdout/stderr 映射到 UART

### 5.1 只处理 stdout/stderr

`_write()` 的 `file` 参数是文件描述符：
- 当 `file` 是 `STDOUT_FILENO` 或 `STDERR_FILENO` 时，视为“终端输出”，走 UART。
- 其它 `file`：设置 `errno = EBADF` 并返回 `-1`。

这使得：
- `printf()`、`puts()`、`fprintf(stdout, ...)` 生效
- `fprintf(file, ...)`（真正文件）在裸机环境仍然不支持（符合预期）

### 5.2 换行转换：`\n` -> `\r\n`

很多串口终端对换行的期望是 CRLF，因此实现里遇到 `\n` 会先额外输出 `\r`。

### 5.3 当前实现的发送策略：逐字节阻塞发送

实现按字符循环：每次调用 `uart_write(..., 1)` 发送 1 字节（必要时额外发一个 `\r`）。

优点：
- 逻辑简单、最容易 bring-up 验证
- 不依赖中断/DMA

缺点：
- 性能较差（大量 HAL 调用）
- 是阻塞式：日志多时会明显拖慢主循环

## 6. `uart_write()`：USART1 的 HAL 发送封装

`uart_write()` 目前使用：

- `HAL_UART_Transmit(&huart1, data, len, 1000)`（阻塞式，超时 1000ms）

返回策略：
- 成功：返回写入字节数
- 失败：返回 `-1`

这意味着 `_write()` 出错时会向上返回 `-1`，从而让上层 `printf` 表现为“写失败”。

## 7. 设计约束与常见坑

- **不要在高优先级中断里直接 `printf`**：阻塞式发送可能导致不可控的延迟，甚至在某些情形下造成死锁/超时。
- **FreeRTOS 多任务并发打印会交错**：当前实现没有互斥，多个任务同时 `printf` 会出现输出穿插。
  - 建议：实现 FreeRTOS 后在 `_write()` 或日志层加互斥（mutex），或做“异步日志队列”。
- **性能问题**：逐字节发送会放大 HAL 调用开销。
  - 建议：做成“块发送 + 仅在需要时做 CRLF 转换”，或使用 DMA/IT + 环形缓冲。
- **只实现了 `_write()`**：如果要支持 `scanf/getchar` 等输入，需要补 `_read()`（并明确阻塞策略与缓存）。

## 8. 如何验证与排查（可复现步骤）

1. 硬件连接（USART1）：
   - 引脚：`PA9`（TX）, `PA10`（RX）（见 `HAL_UART_MspInit()` 的 GPIO 复用配置）
   - 连接：`PA9 -> USB-UART RX`，`PA10 -> USB-UART TX`，并 **共地**
   - 电平：确保是 **3.3V TTL**（不要直接接 RS232 电平）
2. 串口参数：115200，8N1（本项目 `MX_USART1_UART_Init()` 固定为 115200）
3. 运行固件后应看到：
   - `UART retarget ok (USART1 @ 115200)`
   - 每秒一次 `Toggled`

若看不到输出：
- 先确认 `MX_USART1_UART_Init()` 是否被调用
- 确认 `HAL_UART_MspInit()` 是否被调用（GPIO 复用与时钟是否启用）
- 确认 USART1 引脚复用/连线是否正确（硬件层）
- 确认 `HAL_UART_Transmit` 是否返回 OK（可在 `uart_write()` 下断点）

## 9. 可演进方向（建议）

- 方案 A：保持 `_write()` 接口不变，把 `uart_write()` 升级为 DMA + 环形缓冲（对上层透明）。
- 方案 B：把 `printf` 改造成统一日志层（例如 `log_printf`），支持：等级、时间戳、异步输出、互斥、串口/RTT 多后端。
